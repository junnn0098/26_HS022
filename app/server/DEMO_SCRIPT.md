# 발표 시연 스크립트

발표 중 앱·서버 시연을 정해진 순서로 진행하기 위한 체크리스트입니다. 시연은 두 부분으로 나눕니다.

| 구분 | 입력 | 앱의 출처 표시 |
|---|---|---|
| A. 앱·서버 흐름 시연 (기본) | 관리자 페이지 '발표 리모컨' 또는 `jetson_edge_client.py sequence`의 미리 정한 예시값 | '관리자 수동 입력' 또는 '시연 입력' 칩 |
| B. 실시간 센서 연결 (선택) | ESP32-S3 4대 → Jetson 추론 → `live-status` | 'Jetson 실시간 추론' |

A는 보호자 앱이 상태를 어떻게 보여주고 대응을 안내하는지 설명하는 시연이며, 센서 추론 결과가 아닙니다. 발표에서도 A와 B를 구분해 말합니다.

## 1. 실행 준비

서버(`app/server` 폴더). `REAL_SENSOR_ONLY=true`가 없으면 약 45초마다 모의 낙상이 끼어듭니다. 시작 로그의 `Mode: REAL_SENSOR_ONLY=true -> mock motion OFF`를 확인합니다.

```powershell
cd <작업폴더>\app\server
$env:REAL_SENSOR_ONLY="true"
.\run_mock_server_node.cmd
start http://127.0.0.1:8000/admin
```

앱(`app` 폴더, Android 에뮬레이터):

```powershell
cd <작업폴더>\app
.\run_emulator_user_mode.cmd     # 시연 버튼 없는 보호자 화면 (DEMO_MODE=false)
```

앱 설정 화면에서 직접 상황을 바꾸려면 `.\run_emulator_local.cmd`(DEMO_MODE=true, '상황 재연' 버튼 표시)를 씁니다. 실제 휴대폰은 `run_real_phone_example.cmd`의 IP를 노트북 주소로 바꿔 실행합니다. 서버에 `HANIUM_API_TOKEN`을 설정했다면 앱도 `--dart-define=API_TOKEN=<같은 토큰>`으로 실행합니다([서버 설정](README.md#보안네트워크-설정)).

앱 첫 화면은 '역할 선택' 화면입니다. '보호자'를 고르고 '보호자로 시작하기'를 누릅니다.

## 2. 시작 전 확인

| 확인 | 정상 기준 |
|---|---|
| 서버 연결 | 앱 설정 화면 '앱 연결 상태' 카드의 서버 연결이 '준비됨'. 홈에 '마지막 상태를 보여주는 중이에요' 카드가 없음 |
| 초기 상태 | 관리자 '1. 시연 시작'을 누른 직후에는 입력이 없으므로 앱이 회색 '확인 필요'로 표시됨 |
| 모의 이동 | 서버 로그의 `Mode:` 줄이 `mock motion OFF` |

연결이 안 되면 [연결 체크리스트](../docs/CONNECTION_STABILITY.md)를 따릅니다.

## 3. 시나리오 진행 (A)

관리자 페이지 오른쪽 '발표 리모컨'의 버튼을 순서대로 누릅니다. `자동 시연`은 1–6을 자동으로 이어서 실행하고, `멘트 복사`는 발표 멘트 4줄을 클립보드에 복사합니다.

| 버튼 | 서버 상태 | 앱에서 보여줄 것 | 설명 포인트 |
|---|---|---|---|
| 1. 시연 시작 | 초기화(알림 비움) | 회색 '확인 필요' | 입력이 없을 때는 정상 대신 '확인 필요'로 표시 |
| 2. 평소 상태 | `normal`, 거실 | 홈 '정상', '평소와 비슷한 하루예요' | 카메라 없이 WiFi 신호 기반 상태만 보호자에게 전달하는 구조 |
| 3. 현관 접근 | `out`, 현관 | '주의', 집 안 도면의 현관 위치, 알림 '현관 접근이 감지됐어요' | 보호자가 외출 여부를 확인하도록 안내 |
| 4. 무반응 | `still`, 침실-1 | '주의', '오래 움직임이 적어요', 알림 생성 | 연락으로 안부 확인 안내 |
| 5. 낙상 의심 | `danger`, 거실 | '위험', 알림 탭 '빠른 확인이 필요해요', '어르신께 전화'·'119' 버튼, 119 전달 정보 | 확인 → 연락 → 신고 순서, 주소·출입·의료 참고 정보를 한 화면에 |
| 6. 안전 확인 | 알림 확인 처리 후 `normal` | 정상 복귀 | 보호자 확인 후 알림 정리 |

관리자 리모컨 입력은 `source: admin`이므로 홈의 출처 표시는 '관리자 수동 입력'입니다. 비슷한 순서(정상 → 이동 → 현관 접근 → 장시간 무반응 → 낙상 의심 → 정상 복귀)를 터미널(`app/server` 폴더)에서 보내려면 아래 명령을 씁니다. 이때는 `source: scripted_demo`로 들어가 '시연 입력' 칩이 붙습니다. 이 명령은 초기화와 알림 확인 처리를 하지 않으므로 필요하면 관리자 페이지의 '1. 시연 시작'과 '알림 확인 완료'를 함께 씁니다.

```powershell
python jetson_edge_client.py sequence --server-url http://127.0.0.1:8000
```

'현관 접근'·'장시간 무반응'은 앱·서버의 상태 분류입니다. 엣지 연결(`live-status`)은 낙상 상태기계 결과를 정상·위험·확인 필요로 전달합니다([변환 규칙](JETSON_EDGE_CLIENT.md#실시간-추론-결과-연결-live-status)).

## 4. 알림 상세

알림 목록에서 알림 카드를 누르면 예시 재구성 화면이 열립니다. 알림 1건의 위치·상태로 만든 15프레임 예시 흐름이며 실제 기록이 아닙니다. 보호자 확인 순서(도면에서 위치 확인 → 응답 여부 확인 → 즉각 조치 판단)를 설명할 때 사용합니다.

## 5. 피보호자 화면 (선택)

역할 선택에서 '피보호자'로 시작하면 '내 안전 상태' 화면이 열립니다.

- 위치 공유를 끄면 보호자 앱에는 '위치 비공개'로 표시됩니다. 서버는 REST와 WebSocket 모두에서 위치를 숨기고, 이후 알림에도 방 이름 대신 '위치 비공개'를 기록합니다.
- '괜찮다고 알리기'를 누르면 보호자 알림 목록에 '어르신이 괜찮다고 알려왔어요'가 기록됩니다(FCM 푸시는 서비스 계정을 설정한 경우만 실제 단말로 전송).
- 관리자 리모컨 입력에는 호흡값이 없으므로 호흡은 '측정 대기'로 표시됩니다. `sequence` 입력에는 예시 호흡수가 들어 있으며 '시연 입력값'으로 표시됩니다.

## 6. 실시간 센서 연결 (B, 선택)

ESP32-S3 4대와 Jetson이 연결되어 `edge_ai/jetson/run_live.sh`(실시간 추론 파이프라인)가 실행 중일 때만 진행합니다. 관리자 리모컨 입력을 멈추고 [Jetson 엣지 클라이언트](JETSON_EDGE_CLIENT.md#실시간-추론-결과-연결-live-status)의 `live-status`를 실행합니다.

- 앱 출처 표시가 'Jetson 실시간 추론'인지 확인합니다.
- 실행 전 `edge_ai` 폴더에서 `python3 -m hanium_fall_v2.validate_fall_checkpoint models/production/best_model.pt`로 낙상 체크포인트의 `live_ready`를 확인합니다. 체크포인트가 없으면 `fall.state`가 `model_unavailable`이므로 앱은 정상 대신 회색 '확인 필요'를 표시합니다.
- 도면 좌표는 `--room-x`, `--room-y`로 지정합니다.
- `live-status`가 실행 중일 때 추론 결과가 10초 넘게 갱신되지 않으면 '확인 필요'로 바뀝니다. `live-status` 자체를 끄면 서버는 마지막 상태를 그대로 유지합니다.

B는 센서 → Jetson → 서버 → 앱 연결 경로를 보여주는 단계로 소개합니다.

## 7. 마무리 멘트

- 오늘 화면 시연의 상황 입력은 관리자 페이지와 시연 스크립트로 넣었고, 앱은 입력 출처를 구분해 표시합니다.
- 센서 → Jetson → 로컬 서버 → 보호자 앱의 연결 경로를 구현했고, 직접 수집한 CSI 데이터셋(원본 녹화 48건, 5초 윈도우 2,217개)과 학습 결과를 공개했습니다.
- 향후 다양한 사용자·공간의 데이터를 추가로 수집해 새로운 환경에서의 감지 성능을 고도화합니다.

## 8. 문제가 생겼을 때

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/location/latest
```

화면이 다음 단계로 넘어가지 않으면 관리자 페이지에서 `시연 상태 초기화`를 누르거나 정상 상태를 직접 보냅니다.

```powershell
python jetson_edge_client.py once --event normal --server-url http://127.0.0.1:8000
```

그래도 안 되면 앱과 서버를 모두 끄고 서버 먼저, 앱 나중 순서로 다시 켭니다. 주소·포트 문제는 [연결 체크리스트](../docs/CONNECTION_STABILITY.md)를 참고합니다.
