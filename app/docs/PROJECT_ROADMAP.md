# Hanium 앱 완성도 로드맵

이 앱의 핵심은 보호자가 기술 정보를 해석하지 않아도 “어르신이 지금 안전한지”, “어디에서 어떤 일이 있었는지”, “위험하면 무엇을 해야 하는지”를 바로 알 수 있게 만드는 것이다.

## P0. 실행 안정화와 개발 환경

- 앱이 Firebase, 서버, 센서가 없어도 반드시 첫 화면까지 켜져야 한다.
- 개발용 mock 서버를 한 명령으로 실행할 수 있어야 한다.
- 앱에서는 서버 연결이라는 기술 표현 대신 “안심 시스템 정상 작동 중”처럼 보호자가 이해하는 상태로 보여줘야 한다.
- 에뮬레이터 주소(`10.0.2.2`)와 실제 기기 주소를 쉽게 바꿀 수 있어야 한다.
- 위험 시연용 mock 데이터가 있어야 한다.

## P1. 집 안 상태 화면 완성

- 집 도면 위 미니어처가 WebSocket 좌표를 따라 자연스럽게 움직여야 한다.
- 좌표값 대신 방 이름, 자세, 감지 확실성, 최근 확인 시각을 보여줘야 한다.
- 연결 끊김/대기/실시간 연결 같은 개발자 표현은 숨기고, 보호자에게는 “최근 상태를 다시 확인 중”처럼 안내해야 한다.
- 보호자에게는 정확한 감시가 아니라 안전 판단을 돕는 추정 정보임을 자연스럽게 알려줘야 한다.

## P2. 알림과 긴급 대응 실제 기능화

- 낙상, 장시간 무반응, 현관 접근, 센서 끊김을 알림으로 분리한다.
- 위험 알림을 누르면 긴급 확인 화면으로 이동한다.
- “전화하기”, “119 신고 정보 보기”, “확인 완료” 버튼이 실제 상태를 바꿔야 한다.
- 알림 기록을 서버나 로컬 저장소에 남긴다.

## P3. 설정 화면 실제 기능화

- 보호 대상 이름/전화번호/주소 수정
- 보호자 연락처 추가/수정/삭제
- 집 평면도 방 이름 수정
- 알림 기준 시간 설정
- 개인정보 기록 보관 기간 설정

## P4. 서버/API 고도화

- FastAPI 서버를 실제 패키지 환경에서 실행 가능하게 정리한다.
- `/ws/location` 응답 형식을 앱 UI와 맞춘다.
- `/alerts`, `/settings`, `/guardians` 같은 REST API를 추가한다.
- Firebase Admin 인증 파일이 없을 때도 서버가 개발 모드로 켜져야 한다.

## P5. 실제 센서/AI 연동

- Jetson/Raspberry Pi/ESP32에서 CSI 데이터를 서버로 보낸다.
- CSI → 좌표 변환 로직을 mock 대신 실제 알고리즘으로 교체한다.
- 낙상/무반응/외부인 침입 판단 로직을 서버에 넣는다.
- 정확도 평가와 오탐/미탐 기록을 남긴다.

## P6. 발표/심사 완성도

- 시연 버튼 또는 시나리오 모드 추가
- “평상시 → 위험 발생 → 보호자 대응” 흐름 시연
- 개인정보 보호 포인트 강조
- 앱 화면 캡처, 서버 구조도, 데이터 흐름도 준비

## 지금 바로 시행할 순서

1. 완료: P0 안심 시스템 상태를 앱 화면에 표시한다.
2. 완료: P1 집 도면 화면의 실시간 좌표와 최근 이동 경로를 연결한다.
3. 완료: P2 알림 목록, 위험 시연, 확인 완료 흐름을 서버 API와 연결한다.
4. 완료: P3 설정값을 서버에 저장하고 다시 불러오게 만든다.
5. 완료: 관리자 페이지에서 위치/위험 시나리오를 조작하고 앱 도면에 반영한다.
6. 완료: 알림 상세 화면, 신고 문장 복사, 긴급 화면 연결을 추가한다.
7. 완료: 실제 센서 연동용 `/sensor/update` API와 샘플 클라이언트를 준비한다.
8. 완료: 발표 모드와 실사용 모드를 분리해 시연 버튼/문구가 실제 보호자 화면에 보이지 않게 만든다.
9. 완료: 집 평면도 관리에서 방 이름을 수정하고 도면/알림/긴급 화면 문구에 반영되게 만든다.
10. 완료: 개인정보 및 기록 보관 화면을 추가하고 도어락/의료정보/복사 허용 설정을 실제 긴급 화면에 반영한다.
11. 완료: 로그인 화면을 보호자 계정 흐름에 맞게 정리하고, 알림 화면에 개인정보 설정의 기록 보관 기간을 반영한다.

## 다음 우선순위

1. 실제 Android 폰에서 전화/문자/푸시 알림 흐름을 확인한다.
2. Firebase FCM 실제 프로젝트 설정과 `google-services.json`을 연결한다.
3. Jetson/WiFi CSI 장비에서 `POST /sensor/update`로 실제 값을 보낸다.
4. CSI → 좌표/자세/위험 상태 변환 알고리즘을 mock 대신 연결한다.
5. 로그인/보호자 계정 구조를 실제 인증 방식으로 확장한다.
6. 개인정보/도어락 정보 암호화와 접근 권한 정책을 정리한다.
7. UI/UX 상세 설계와 실제 앱 화면이 계속 일치하는지 점검한다.
8. 발표 자료용 구조도와 시연 영상/스크린샷을 만든다.
