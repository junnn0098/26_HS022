# 설계 요구사항과 현재 구현

검토 기준은 저장소 `cad2600`, 사용자 제공 **한이음_제작설계서.pdf(32쪽)**, **한이음_개발보고서_최종.pdf(23쪽)**입니다. 문서 쪽수는 PDF의 첫 페이지부터 셉니다. 원본 PDF는 공개 허용 범위를 확인하지 않았으므로 이 저장소에 재배포하지 않았습니다.

여기서 ‘코드 확인’은 해당 처리 코드가 있다는 뜻입니다. 센서·학습 모델·실제 스마트폰을 사용한 실험 완료와 구분합니다. 이번 문서 보완에서는 아래에 기록한 기능상의 문제를 해결했다고 주장하지 않습니다.

## 입력 규격의 기준

| 항목 | 문서 간 차이 | 현재 코드 근거와 사용할 표현 |
|---|---|---|
| 수신률 | 설계서 p.5·10은 100Hz, p.21은 약 33pps | 약 33pps는 팀의 수집 조건. `features.py`는 실제 수신 시각을 32Hz로 보간하므로 수신률과 보간률을 구분 |
| 입력 크기 | 설계서 p.22는 52×500, p.26 및 보고서는 134×500, 설계서 p.21은 193×160 | `FeatureConfig`와 `default_config.json`: 노드별 193×160, 최대 4노드, 5초 창 |
| LTF 선택 | 설계서 p.21의 그림은 LLTF, 본문은 HT-LTF | `adr018.py::extract_lltf_iq`: 첫 LLTF 64개, 앞 2개 복소수 마스킹, 20MHz·PPDU 검사 |
| 노드 융합 순서 | 설계서 p.21은 입력을 attention으로 먼저 합치는 것으로 읽힘 | `model.py`: 노드별 공유 1D-CNN 인코딩 후 attention 가중 융합 |
| 낙상 판정 | 설계서 p.13은 P≥0.9, 다른 곳은 시간·공간 필터 | `fall_state.py`: 후보·사후 눕기·회복 확인. 임계값은 아래 설정표 기준 |
| 배포·지연 | TensorRT·0.01초 설명과 ‘목표’ 표현 혼재 | 현재 공개 추론 경로는 PyTorch. TensorRT 실행 코드·엔진·지연 측정 결과는 확인되지 않음 |

현재 기본값의 출처: [설정](../edge_ai/config/default_config.json), [특징 추출](../edge_ai/hanium_fall_v2/features.py), [패킷 파서](../edge_ai/hanium_fall_v2/adr018.py), [모델](../edge_ai/hanium_fall_v2/model.py).

| 상태기계 항목 | 기본값 | 해석 |
|---|---|---|
| 추론 주기 | 0.5초 | 입력 창 5초와 별개 |
| 최소 품질 | 0.55 | 낮은 품질의 판단을 유보. 사후 확인·확정 상태는 별도 유지 규칙 적용 |
| 낙상 후보 | fall≥0.70, 누적 2회 | 조건 미충족 시 후보 횟수 감소 |
| 사후 눕기 | lying≥0.55, 누적 3회 | 연속 3회 조건은 아님 |
| 회복 | 서기·걷기·일어서기 확률 중 최대값≥0.65, 누적 2회 | 확정 전 사후 확인에서 회복 여부 판단 |
| 사후 확인 제한 | 8초 | 확정·회복이 없으면 정상으로 복귀 |
| 확정 경보 유지 | 최소 30초 | 30초 경과만으로 해제하지 않고 이후 회복 조건도 확인 |

이는 설정값이며 검출 정확도나 전체 알림 지연의 보장값이 아닙니다.

제작설계서 p.19·24~25의 ERD는 확장 설계입니다. 현재 Node.js 서버는 `dev_state.json`을 사용하며 해당 테이블을 운영하는 DB 구현과 구분합니다. 호흡·기침 연구 코드가 있다는 사실을 의료적 진단 성능으로 해석하지 않습니다.

## 성능 자료의 해석

- 개발보고서 p.19: 초기 502개 클립에서 재현율 1.0·오탐 0건.
- 개발보고서 p.15·19: 1,019개 클립(낙상 302건, 11종 동작)에서 재현율 0.933, 휘청임 동작 오탐 0건.
- [수집 CSV](data_collection/collection_log.csv): 36개 녹화 기록. 녹화 세션, 잘라낸 평가 클립, 모델 학습 창은 서로 다른 단위입니다.
- 원본 데이터·분할 목록·가중치·예측 로그가 없어 보고서 수치를 현재 코드로 재현하지 않았습니다. 현재 10종 라벨과 보고서의 11종 동작을 연결하는 대응표도 필요합니다.
- `acceptance_check.py`의 기본 낙상 재현율 기준 0.95는 코드에 설정된 목표입니다. 보고서 수치 0.933을 해당 기준 통과로 표현하지 않습니다.

추가 공개할 평가 자료에는 모델 해시, 평가 대상·피험자·환경, 분할 방식, 라벨 대응표, 클래스별 support·precision·recall·F1, confusion matrix를 함께 기록합니다. 장기 오탐은 관찰 시간과 오경보 건수를 함께, 알림 지연은 시작·종료 지점과 중앙값·상위 지연을 함께 기록합니다.

## 우선 보완할 구현 항목

아래는 코드 점검 및 제한된 로컬 재현에서 확인한 사항입니다. 문구 변경만으로 해결되는 문제가 아닙니다.

| 우선순위 | 확인 사항 | 코드 위치 | 완료 조건 |
|---|---|---|---|
| 높음 | 연결 클라이언트는 없는 호흡값을 생략하지만 서버가 상태별 예시값으로 보충. 앱의 `_applyLocation()`은 서버의 `breathingEstimated`를 읽지 않고 숫자 존재 여부로 다시 판단 | `app/server/dev_mock_server.js::normalizeLocation`, `app/lib/core/state/safety_controller.dart::_applyLocation` | 값 없음·예시값·실측값 구분을 서버부터 화면까지 보존. 실측값이 없으면 측정 대기로 표시하는 테스트 |
| 높음 | `unknown`·`model_unavailable`도 경보가 없으면 `normal`로 전달 | `app/server/jetson_edge_client.py::payload_from_live_status` | 판단 불가·모델 미설치를 앱에 별도 전달하고 정상으로 오인하지 않는 테스트 |
| 높음 | `live-status`는 시각 변경 여부만 비교하고 오래된 레코드의 나이를 검사하지 않음. 서버의 `REAL_SENSOR_ONLY` 경로도 마지막 상태를 유지 | `command_live_status`, `dev_mock_server.js::currentLocation` | 센서·추론·연결 클라이언트 중단 시 데이터 만료를 구분하고 마지막 수신 시각 표시 |
| 중간 | 도면 위치가 고정 설치 좌표이고, 경로 표시를 실제 추정 동선으로 오해할 수 있음 | `--room-x`, `--room-y`, `model.py` | 화면·영상에 위치 출처 표시. 자동 추정 도입 시 위치 정답과 오차 평가 추가 |
| 중간 | 단순 JSON 경로는 `lying`을 곧바로 위험으로 매핑하며 상태기계 경로와 다름 | `LABEL_TO_EVENT`, `payload_from_ai_record` | 현재 모델 연결은 `live-status` 사용. 단순 입력 경로의 용도를 시연으로 명확히 제한 |
