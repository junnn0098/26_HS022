# 합성 입력 기반 소프트웨어 검증 결과

센서와 학습 가중치 없이 합성 입력으로 상태기계, 호흡 추정기, 패킷·노드 누락 처리, 서버 연동이 정한 대로 동작하는지 확인한 결과입니다. 낙상 감지 모델의 성능은 [실측 데이터 학습 결과](MEASURED_RESULTS.md)에 있습니다. 실행 방법은 [실험 안내](README.md)에 있습니다.

1–3절은 2026-10-18에 `b3bc7e4`에서 실행한 결과이며, 실행 환경·설정·입력 파일 해시는 [environment.json](results/2026-10-18/environment.json)에 있습니다. 이 결과에 쓰인 `edge_ai/hanium_fall_v2`의 모듈 4개(`config.py`, `fall_state.py`, `features.py`, `respiratory.py`)와 [시나리오 파일](fall_scenarios.json)은 2026-10-19 현재도 기록된 해시(LF 기준)와 같으므로 1–3절 결과는 현재 코드에 그대로 해당합니다. 4절의 서버 연동은 현재 서버 코드로 2026-10-19에 확인했습니다.

## 1. 낙상 상태기계 시나리오

0.5초마다 미리 정한 행동 확률을 상태기계에 넣었습니다. 기본 확률은 지정 행동 0.9, `other_motion` 0.1이며, 저품질·빈 방 시나리오만 품질·인원 조건을 변경했습니다. 모델 추론을 통과한 입력이 아닙니다.

| 시나리오 | 관측 결과 |
|---|---|
| 평상시 / 한 번만 높은 낙상 확률 | 경보 없음 |
| 낙상 확률 누적 후 눕기 | 최초 입력 후 2.5초에 `confirmed` |
| 확정 전 다시 서기 | 경보 없이 `recovered` |
| 눕기·회복 근거 없이 제한 시간 경과 | `normal`로 복귀 |
| 낮은 품질 | `unknown` |
| 확정 후 빈 방 예측 / 품질 저하 | 확정 경보 유지 |
| 눕기 사이에 다른 행동 삽입 | 누적 3회가 되면 3.5초에 확정 |
| 확정 후 계속 서기 | 최초 입력 후 33.0초에 회복, 경보 확정 시점으로부터 30.5초 |

10개 시나리오 모두 지정한 기대 결과와 일치했습니다. 2.5초는 주입한 확률을 상태기계가 처리한 시간이며, CSI 수집·5초 입력 창·모델 계산·통신·앱 표시 시간은 포함하지 않습니다. 눕기 판정은 연속 3회가 아니라 누적 3회 기준입니다.

## 2. 합성 호흡 주파수 추정

32Hz·61초, 64개 복소 값 중 앞 2개를 0으로 가린 signed int8 배열을 생성했습니다. 각 성분은 `real=35+7·sin(2πft+phase)+noise`, `imag=8+2·sin(2πft+phase)+noise`이며, `phase=0.02×서브캐리어 인덱스`입니다. 실수·허수 잡음은 독립 정규분포입니다. 주파수는 8.0·12.3·15.0·20.7·27.4회/분을 사용해 FFT 정수 bin과 비정수 bin을 함께 포함했습니다.

| 잡음 표준편차(IQ 정수값 단위) | 시행 수 / 추정 반환 | 평균 절대 오차(회/분) | 최대 절대 오차(회/분) |
|---|---|---|---|
| 0.0 | 15 / 15 | 0.0413 | 0.0726 |
| 0.7 | 15 / 15 | 0.0404 | 0.0719 |
| 3.0 | 15 / 15 | 0.0386 | 0.0839 |
| 8.0 | 15 / 15 | 0.0449 | 0.0862 |

각 수준은 주파수 5개와 시드 3개의 조합이며, 잡음 0에서는 시드 3회의 입력이 같습니다. 오차는 반환된 추정값으로 계산하며 60회 모두 값이 반환됐습니다. 이 오차는 고정 주파수 합성 사인파의 복원 결과이고, 잡음 표준편차는 IQ 정수값 단위입니다.

![합성 주파수 추정 실험](results/2026-10-18/respiration_sweep.svg)

영 신호·상수 신호·20초 이력·3초 오래된 입력에서는 추정값을 내지 않았습니다. 백색잡음 입력에서는 단일 노드 추정기가 약 24.65회/분을 계산하고 신뢰도 약 0.200을 붙였으며, 이는 기본 신뢰도 기준 0.45보다 낮습니다. 운영 경로의 `RespiratoryMonitor`는 노드 수·신뢰도·움직임 조건을 함께 적용하므로, 신뢰도 점수로 저신뢰 추정을 구분합니다. 이 실험은 단일 노드 추정기 단위 검사입니다.

## 3. 패킷 누락과 품질 점수

5초 동안 약 33pps인 165개 타임스탬프에서 패킷을 제거했습니다. 누락률은 0·10·25·50·75·90%, 패턴은 무작위 제거와 중앙 연속 구간 제거, 시드는 3개입니다. 양 끝 패킷을 유지해 시간 범위와 패킷 개수가 같은 경우를 비교했습니다. 36회 모두 유한한 특징 배열을 생성했습니다.

| 약 50% 누락, 시드 7 | 남은 패킷 | 최대 패킷 간격 | 품질 점수 |
|---|---|---|---|
| 무작위 누락 | 83 | 0.212초 | 0.51875 |
| 중앙 연속 누락 | 83 | 2.515초 | 0.51875 |

품질 점수는 `시간 범위 커버리지 × 패킷 밀도`로 계산하므로, 시간 범위와 남은 패킷 수가 같으면 무작위 누락과 연속 누락의 점수가 같습니다. 두 경우 모두 노드 마스크 기준 0.25를 넘으며, 최대 패킷 간격은 연속 누락에서 2.515초입니다. 향후 최대 패킷 간격·구간별 커버리지를 품질 점수에 반영해 고도화할 계획입니다. 무작위 패턴의 세부 간격은 시드에 따라 달라지며 그림에는 시드 7을 표시했습니다. 연속 누락은 시드와 무관합니다.

![패킷 누락 실험](results/2026-10-18/packet_loss.svg)

노드를 0·1·2·4개 제공한 경우 텐서 크기는 모두 `(4, 193, 160)`이었고 존재하는 노드만 마스크에 반영됐습니다(입력 구성 검사).

## 4. 서버 연동과 기존 검사

임시 로컬 서버(`local_server.js`)와 Python 연결 클라이언트(`jetson_edge_client.py`)에 합성 `live-status` JSON을 전달했습니다. 서버는 `127.0.0.1`에만 바인딩했고 Firebase 설정·API 토큰·사용자 상태 파일은 사용하지 않았습니다.

| 관측 항목 | 결과 |
|---|---|
| 입력 전 초기 상태 | `unknown` (앱 표시: 확인 필요) |
| 확정 경보 입력 | `danger` 전달 |
| 호흡값 18.2 입력 | 18.2 유지, `breathingEstimated=false` |
| 모델 미설치(`model_unavailable`) 입력 | 연결 클라이언트와 서버 모두 `unknown` |
| 호흡값 누락 | 연결 클라이언트는 생략하고 서버도 `breathingRate: null`, `breathingEstimated=false` |
| `unix_time=1`인 오래된 결과 | 연결 클라이언트가 결과 대신 `unknown`을 보내고 `[stale]` 출력·종료 코드 1, 서버 상태는 `unknown` |

기대 항목 13개가 모두 관측값과 일치했습니다. 18.2는 주입한 예시값이며, Flutter 화면과 FCM 단말 수신은 이 검사의 범위 밖입니다.

단위 테스트와 자체 점검 결과는 [기능별 구현 현황의 확인 기록](../docs/IMPLEMENTATION_STATUS.md#확인-기록)에 있습니다.
