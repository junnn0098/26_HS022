# 실측 데이터 검증 결과

팀이 직접 수집한 [CSI 데이터셋](../dataset/README.md) 2,217개 윈도우로 낙상 감지 모델을 다시 학습·평가했습니다. 같은 데이터를 세 가지 방식으로 나누어 평가해, 보고서 수치가 어떤 조건에서 나오는지와 실제 설치 환경에서 기대할 수 있는 성능을 구분했습니다.

## 요약

1. **보고서 결과는 재현됩니다.** 보고서와 같은 1,019개 윈도우를 무작위로 80/20 나누면 낙상 재현율 0.997, 비틀거리기(넘어지지 않음) 오탐 0건입니다(보고서: 재현율 0.933, 비틀거리기 오탐 0건).
2. **무작위 분할 성능에는 녹화 식별 효과가 섞여 있습니다.** CSI가 아닌 패킷 헤더 5채널만 넣어도 재현율 0.970이 나옵니다. 같은 녹화의 이웃 구간이 학습·시험에 함께 들어가므로, 모델이 동작보다 "어느 녹화인지"를 알아볼 수 있습니다.
3. **처음 보는 녹화·다른 날에는 아직 일반화되지 않습니다.** 녹화 단위로 나누면 AUROC 0.54, 날짜로 나누면 0.71 이하이며, 실시간용 v2 파이프라인도 같은 평가에서 비슷한 수준입니다. 07-17 팀 가중치는 이후 수집한 07-24·07-28 데이터에서 낙상을 하나도 찾지 못했습니다.
4. **원인은 모델보다 데이터 쪽에 있습니다.** 라벨이 녹화 단위로 붙어 있고, 노드가 보내는 패킷 형식이 섞여 있으며, 동작에 따른 CSI 변화량이 다른 변동보다 작습니다(아래 5절). 다음 수집은 이 세 가지를 고치는 방향으로 설계합니다.

## 평가 방법

| 항목 | 내용 |
|---|---|
| 데이터 | [`dataset/metadata/windows.csv`](../dataset/metadata/windows.csv)의 5초 윈도우 2,217개, 녹화 45건, 낙상 969개 |
| 라벨 | 녹화 단위 라벨에서 낙상(`fall`) = 1, 나머지 14종 = 0 |
| 분할 | **윈도우 무작위**: 라벨별 층화 80/20 · **녹화 단위**: 녹화 45건을 5겹으로 나눠 같은 녹화가 학습·시험에 동시에 들어가지 않음 · **날짜 단위**: 07-08~07-15로 학습, 07-24·07-28(새 참여자 S2 포함)로 시험 |
| v1 | `CSI1DCNN`, 134채널 × 500, 윈도우 z-score, 가중 교차 엔트로피, Adam(1e-3) + cosine, 25 epoch, 배치 32 |
| v2 | 노드별 LLTF 64개 → 193채널 × 160프레임, `MultiNodeFallModel`, 행동 10종 + 인원 + 품질 손실(v2 학습 코드와 같은 가중치), AdamW(1e-3) + cosine, 25 epoch, 학습 데이터 증강 |
| 판정 | 낙상 확률 ≥ 0.5. 확률 순위만 보는 AUROC(0.5 = 무작위 추측)를 함께 보고 |
| 환경 | CPU(PyTorch 2.x), 시드 고정. 반복 실험은 평균 ± 표준편차, 검출 수는 반복 합계 |

## 1. 보고서 수치의 재현

보고서 4.4절과 6.2절의 1,019개 윈도우(07-08·07-09, 11종 동작, 낙상 302개)를 라벨별 층화로 80/20 나누어 5번 반복하면, 시험 낙상 300개 중 299개를 찾고 비틀거리기 윈도우 55개(5회 합계)는 한 번도 낙상으로 판정하지 않습니다. 보고서의 재현율 0.933과 비틀거리기 오탐 0건은 이 분할 방식에서 나온 값으로 판단됩니다.

## 2. 무작위 분할이 높게 나오는 이유

- 134채널 중 0~4번은 CSI가 아니라 패킷 헤더 값(주파수, 패킷 순번, RSSI, 잡음, 플래그)입니다. 이 5채널만 입력해도 재현율 0.970, AUROC 0.992가 나옵니다. 패킷 순번과 RSSI는 녹화마다 다르므로 녹화를 구분하는 단서가 됩니다.
- 라벨이 녹화 단위라 녹화를 알아보면 라벨도 맞힐 수 있습니다. 같은 녹화의 연속된 5초 구간이 학습과 시험에 나뉘어 들어가면 이 지름길이 열립니다.
- 녹화를 통째로 시험에 두면 AUROC가 0.54로 떨어집니다. 1,019개 세트만 써도 0.55입니다.

## 3. 다른 날의 데이터

- 07-17 팀 가중치를 07-24·07-28에 적용하면 낙상 359개 중 0개를 찾습니다. 확률 순위(AUROC 0.72~0.79)는 남아 있지만 모든 확률이 0.5 아래로 내려갑니다.
- 07-24부터는 노드가 보내는 패킷의 폭이 대부분 198로 바뀌어, 134채널 중 69~133번의 의미가 달라집니다([채널 구성](../dataset/README.md#134채널의-실제-구성)). 헤더를 빼거나(`csi`) 의미가 같은 LLTF 64개만 써도(`lltf`) 날짜 분할 AUROC는 0.49~0.53입니다.

## 4. v2 파이프라인으로 같은 평가

실시간 서비스용으로 다시 설계한 v2(노드별 분리, LLTF 고정 선택, 32Hz 보간, 노드 attention 융합)를 같은 윈도우·라벨·분할로 학습했습니다([`v2_measured.py`](v2_measured.py)). 원본 녹화를 v2 세션 형식으로 바꾸는 과정은 [`raw_to_v2.py`](../dataset/tools/raw_to_v2.py)에 있습니다.

| v2 평가 | 낙상 재현율 | AUROC |
|---|---:|---:|
| 녹화 단위 5겹 | 0.001 | 0.470 ± 0.110 |
| 날짜 분할, 3회 | 0.000 | 0.499 ± 0.035 |
| 녹화 단위 5겹, 192폭 패킷만 | 0.000 | 0.496 ± 0.134 |
| 날짜 분할, 192폭 패킷만, 3회 | 0.225 ± 0.318 | 0.497 ± 0.003 |

v2는 낙상 확률을 0.5 넘게 내는 경우가 거의 없었고, 확률 순위도 무작위 추측 수준(AUROC 0.47~0.50)이었습니다. 5절의 진단에서 가장 나았던 192폭 패킷만 써도 같았습니다. 학습 손실은 줄었지만(2.1~2.2 → 1.2~2.0) 학습한 규칙이 다른 녹화로 옮겨가지 않았습니다.

입력 처리를 바꿔도 처음 보는 녹화에서 성능이 오르지 않았으므로, 지금 병목은 모델 구조가 아니라 학습 데이터라고 판단합니다.

## 5. 신호 진단: CSI가 동작을 얼마나 담고 있나

모델 없이 계산한 움직임 지표(노드별 첫 LLTF 블록의 로그 진폭에서 패킷별 이득 변화를 빼고, 5초 동안의 서브캐리어별 표준편차를 평균)로 "움직이는 동작(걷기·낙상 등)"과 "정지 동작(앉아 있기·서 있기·누워 있기)"을 얼마나 구분하는지 보았습니다([`signal_diagnostics.py`](signal_diagnostics.py), [결과 JSON](results/diagnostics/motion_signal.json)).

| 사용한 패킷 | 움직임 vs 정지 AUROC | 낙상 vs 나머지 AUROC |
|---|---:|---:|
| 모든 폭 | 0.601 | 0.503 |
| 128폭만 | 0.514 | 0.433 |
| 192폭만 | 0.728 | 0.713 |

- 모든 패킷을 섞으면 앉아 있는 녹화와 걷는 녹화의 CSI 변화량이 거의 같습니다. 동작에 따른 변화보다 다른 변동(패킷 종류별 이득 차이, 노드 배치 변화 등)이 더 큽니다.
- 192폭 패킷만 쓰면 지표 하나로도 구분 정도가 올라갑니다. 패킷 형식을 하나로 고정하는 것이 다음 수집의 첫 조건입니다. 이 표는 모든 날짜의 데이터를 보고 만든 진단이므로, 192폭 선택의 효과는 아래 v2 결과(192폭만 사용)와 새 수집 데이터로 확인해야 합니다.

## 6. 다음 단계

1. **펌웨어·공유기 설정 고정** : 노드가 한 가지 PPDU 형식(폭)의 패킷만 보내도록 설정하고, 수집 시작 전에 노드별 패킷 폭·수신량을 [`validate_multinode_stream.py`](../edge_ai/hanium_fall_v2/validate_multinode_stream.py)로 확인합니다.
2. **사건 단위 라벨** : 5분 녹화 전체에 같은 라벨을 붙이지 않고, 웹캠 관절 좌표로 넘어지는 순간을 찾아 그 전후 구간만 `fall`로 둡니다. [`pose_events.py`](../dataset/tools/pose_events.py)의 몸통 하강 지표가 출발점입니다. v2 수집 도구 [`capture_labeled.py`](../edge_ai/hanium_fall_v2/capture_labeled.py)는 이미 사건 시각을 기록합니다.
3. **빈 방·정지 기준선** : 사람이 없는 방과 가만히 있는 사람의 기록을 함께 모아 움직임이 없을 때의 CSI 변동 범위를 정합니다.
4. **평가 기준** : 모든 수치는 녹화 단위 이상으로 나누어 보고하고, 무작위 분할 결과는 비교용으로만 씁니다.

## 재현

```bash
python dataset/tools/download.py --v2                     # 학습 윈도우 + v2 세션 (약 345MB)
python experiments/run_v1_experiments.py                  # v1 전체 (CPU 약 15분)
python experiments/v2_measured.py --protocol recording --threads 2 --out experiments/results/v2_measured/recording
python experiments/v2_measured.py --protocol temporal --seeds 0 1 2 --threads 2 --out experiments/results/v2_measured/temporal
python experiments/signal_diagnostics.py
python experiments/make_results_table.py                  # 위 결과 표
python experiments/plot_figures.py                        # 그림
```

결과 폴더마다 `summary.json`(평균·표준편차), `runs.json`(반복별 지표·동작별 낙상 판정 비율·학습 손실), `predictions.csv`(윈도우별 낙상 확률)가 있습니다.
